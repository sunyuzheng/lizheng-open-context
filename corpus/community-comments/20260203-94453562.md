> [查看原评论及上下文](https://www.superlinear.academy/c/share-your-projects/ai-architect-agent-debugger#comment_wrapper_94453562) · 发布于 2026-02-03 · 原始讨论公开可见。仓库只收立正本人的回复，已移除成员提及名称、联系方式和正文链接；原帖和其他成员的话不在本仓库许可范围内。

到了 Opus 4.5 之后会发现，Claude Code 在打开 Plan Mode 以及 Opus 4.5 的加持之下，其实整个开发过程变成了一个“自动挡”。新模型的 concurrent tasking、long-running task support 以及 error resilience 都得到了极大的增强。除了非常难的一些问题需要引入 Codex，把模型换到 GPT 5.2，并且将 Reasoning Effort 开到 Extra High 之外，其他问题基本上都可以使用 Claude Code 解决。

当然这里也有一个痛苦的点，就是之前写的 agentic loop 在 Opus 4.5 下其实已经完全没用了。因为我发现它们完全是为长程任务中的 error resilience 设计的，但是 Opus 4.5 在 error resilience 上是非常强的。Opus 4.5 缺少的是 recover from errors 的能力，也就是经历了太多错误之后依然会目标漂移，无法从错误中恢复到既有目标。不过这种情况需要非常极端的情况才能够出现。相较而言，Opus 4.5 的工具调用以及 error resilience 都要比 Opus 4.1 强太多了。

不过这里要感谢课代表，是看了课代表 1 月份的视频（做事快与慢）我才下定决心把被 Opus 4.5 废掉的 agentic loop 给彻底抛弃掉。因为很明显，这个 debugger 项目我认为更重要，作为个人履历上的作品更具有冲击力。另外，在 agent runtime 上再起一套 agentic loop 也不符合第一性原理。

让我想起了 #为什么学习Agentic AI的第一步是忘记所有框架？  。你的时间精力没有浪费，让你内化了AI应用开发过程中，很多人都要踩的坑，相信你看了这篇文章也会有更多共鸣。

这个idea真的很不错，但是我水平有限，没办法技术上评价太多。期待 [社区成员] 鸭哥 评价一番。
