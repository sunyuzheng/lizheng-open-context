> 原文：[对话麻省理工长毛兔：技术小白如何跟上AI时代｜小红书如何涨粉？](https://www.superlinear.academy/c/recording/mit-jenny) · 发布于 2026-06-14 · 原始空间公开可见。本文保留发表时语境；其中第三方引文、发言、链接与商标不随正文重新授权。

这期直播我请到的是 Jenny，大家更熟悉的名字是「麻省理工长毛兔」。

她适合聊这期，不是因为她站在工程师的位置教普通人写代码。她自己有主业，周末和下班学 AI 和 vibe coding；本科工业工程，研究生学 BA 和土木环境工程，做过产品、数据分析、数据工程和多年管理咨询。她真正有价值的地方，是她保留了小白跨门槛时的体感：从 Chat 到 Code、从图形界面到 Terminal、从「看教程」到「真的上线一个有人用的产品」，每一步哪里卡、哪里怕、哪里花钱，她都讲得很具体。

所以这期聊的不是某一个 AI 工具。它实际回答的是几个普通人现在最关心的问题：没有开发背景，怎么开始用 AI 做东西；vibe coding 到底要花多少钱；怎么把一个想法做成产品雏形；小红书为什么能涨起来；看起来像朋友聊天的表达，背后要付出多少剪辑成本；以及当一个 AI 自媒体账号开始有信任和流量之后，商单、知识付费、产品化的边界在哪里。

## **06:20｜普通人下班学 AI，这个身份先定住**

一开始我问 Jenny 怎么介绍自己。她没有把自己包装成技术博主，而是说自己是「一个比较愿意学习，然后分享自己的学习过程和成果的人」。

她说：

> 我之所以说自己是普通人下班后学习 AI，是因为我现在有自己的主业，同时也会在周末和下班的时候去学一些 AI 和 vibe coding 的东西。但是我并没有一个开发的背景，以前没有做过 software engineering、development 这种技术开发。

她后面补充，自己虽然没有开发背景，但做过产品、数据分析、数据工程和管理咨询，兴趣比较综合，最近半年到一年最上头的是 vibe coding。

这段很重要。很多人想学 AI，但一看到「工程师」「代码」「终端」就觉得这件事跟自己无关。Jenny 的视角刚好卡在中间：她不是纯技术背景，却也不是只停留在和 AI 聊天。她已经跨过一部分门槛，所以能讲清楚那个门槛到底长什么样。

## **08:22｜学 AI 花了多少钱：两三千美金里，一半是电脑**

我问她以前统计过自己在 AI 和 vibe coding 上花了多少钱。她说，当时数过，大概两三千美金，但「差不多一半是在买电脑上」。

她原来一直用 Windows，后来为了做 iOS development，专门买了一台 Mac。她也把日常订阅拆开讲：Claude Code、Lovable、domain、hosting，加起来一个月大概五六十美金。更贵的 Max 她一直拖着没上，因为只有偶尔几天觉得不够用。

这个数字的好处是，它把「学 AI 很烧钱」讲实了。钱确实花了，但不是一个模糊的焦虑。电脑是阶段性投入，订阅是根据使用频率慢慢加的。对大多数普通人来说，先不用把自己想象成一天烧掉巨量 token 的重度用户。你要做什么，决定你需要花多少钱。

## **12:50｜第一次尝到甜头：自然语言做网页**

Jenny 真正开始，是在湾区参加 Ready AI 的分享会。她看到有人用自然语言直接做网页，一下子被击中。

她说自己从小就想做网页，但每次看到 HTML、CSS 一大堆要先学的东西，就劝退了。那次 demo 让她发现，原来可以先用自然语言把网页做出来。后来她又从 n8n、low code、no code 开始，做 Reddit 监测、邮件自动处理，再到 Lovable。

她讲 Lovable 时用了一个很直接的说法：

> Lovable 就是一个打开新世界大门的东西，因为它立刻就可以看到你想要做的事情。

这段适合给还没开始的人看。很多人并不是没有想法，也不是没有学习能力，而是被「开始之前必须先学完一堆东西」卡住了。AI 工具改变的第一件事，是你可以先做出一点东西。看到结果之后，人会更愿意继续学。

## **17:47｜第一个有人用的产品：圣诞卡片和三位数 API 账单**

她第一个真正上线、有人用的产品，是一个圣诞卡片小工具。用户上传照片，她用 prompt 把照片生成好看的卡通图片，再做成圣诞卡片发给别人。

这个产品后来有几千个人用。她说小红书给了很多支持，大家都来试。因为用户太多，Resend 还冻结过她的账号，她得去解释。最花钱的地方，是她自己出钱让大家用 API 做图。

> 我应该是刷了三位数的 API 吧，然后我就一直在补。三位数还好。

这个细节很有价值。几千人用、还涉及图片生成的 AI 小产品，最后不是一个天文数字。她也不是被这笔钱吓退，而是意识到成本是可以管理的：手动充值，快不够了提醒一下，再补。

这对很多想做 AI 小产品的人是一个具体参照。担心成本可以，但不要把成本想象成一个不可触碰的黑洞。

## **19:52｜AI 产品上线后，才知道真正的问题在哪**

从圣诞卡片开始，Jenny 讲到 AI 产品和传统 SaaS 的差别。她说，以前很多软件是 build once，用户从 10 个到 100 个，边际成本差别没那么大。但 AI 产品不是这样。

> AI 时代的话，不是说你加一个用户就基本上没加什么钱。每个用户都是实打实的 AI tokens 那种钱。

更重要的是，上线之后才会出现真正的问题：账号冻结、API 出问题、database 出问题、凌晨三四点修 bug。她说那段时间经常睡得很晚，因为「下一秒又有人登录网站的话，我可能就觉得有点对不起大家」。

但她不觉得这只是麻烦。她说：

> 这东西得上线了你才能学到一些东西。
如果有人在用，然后立刻在你的评论区给你提供 feedback，然后你就马上去改，这是一个非常健康的 loop。

这段把 vibe coding 从「好玩」拉到了真实产品。只在本地做 demo，学不到上线后的责任感，也学不到用户怎么用、哪里会坏、哪里值得改。

## **29:40｜比起出 bug，她更怕没人用**

我问她，会不会担心上线后出了问题自己修不了。她说小 bug 不是最怕的，真修不了可以找朋友求助。她更担心的是另一件事：

> 比起出现这种问题，我更担心的是没有人用。就是发出去以后没有人用，没有水花。

后面她讲到最近做产品的两难：她看到的问题，往往很难做出完整 solution；她能做出来的 solution，又很难找到客户和 ICP。最后还是回到 product market fit。

这句话很打中做技术的人。很多人把「能不能做出来」当成第一关，做完之后才发现，让别人关心、愿意试、愿意持续用，才是更难的那一关。AI 让做产品变快了，但它没有替你解决「为什么别人要用」这个问题。

## **31:45｜从 1.8 万到 10 万粉：频率上去，成本降下来**

Jenny 2022 年入学麻省理工时开始做小红书，最早拍校园 vlog。两年下来大概 1.8 万粉。后来 2025 年开始更规律地分享 vibe coding，9 月、10 月左右稳定更新，当时大概两三万粉，到年初破 10 万。

她讲涨粉，没有讲玄学，讲的是一个很朴素的系统：

> 有那么三四个月是每周发三个视频。
周日坐下来把三个视频全录了，我不会一周分三次去录。女孩子又要洗头发又要化妆，比较麻烦。

她会周日集中录完三条，剪辑分开做。这样每条视频的心理成本就降下来了。

这段对做自媒体的人很实用。所谓稳定更新，很多时候不是意志力问题，是系统问题。一次准备，多条产出，把每次开机、布置、化妆、进入状态的成本摊掉，频率才上得去。

## **35:45｜观众缘和清楚表达，背后是 20 分钟剪成 3 分钟**

我说她的视频有观众缘，表达清楚，节奏舒服。她的回答很诚实。

她觉得观众缘可能和性格有关，像「一个朋友在网上一样」。但表达清楚这件事，她不觉得自己天生就好。

> 我大部分时候还是靠后期去剪辑的。
一句话可能会讲很多次才能把它讲清楚。
一个三分钟、五分钟的视频，我可能录了 15 分钟到 20 分钟，然后剪到三分钟、五分钟。

这段拆掉了一个常见误解：观众看到的自然，不等于制作过程轻松。看起来像朋友聊天，背后有大量重录、删减和取舍。她不是用豪华制作堆出来的，而是用剪辑把真实口语里的重复、卡顿和绕路去掉。

## **40:28｜中英文夹杂不是装，是概念检索路径**

聊到表达时，Jenny 提到很多人不喜欢听中英文夹杂。她说，在海外住久了，或者在外企工作久了，专业词汇第一反应就是英文。有时她会尽量讲纯中文，但想不到中文怎么说，就会停顿或卡住。

我补了一层解释：我们脑子里先有概念，概念本身不是语言。平时接触某个概念主要用英文，第一反应就会映射到英文。如果强行翻译成中文，还要多插入一个任务，思路会慢下来。

Jenny 接得很像她本人：

> 所以说到底我人脑还是懒的，就是挑手边最近、最合适、最快能抽取到的词就开始用了。

这段对海外华人、外企职场人、内容创作者都很有共鸣。它把「中英文夹杂」从风格争议，变成了语言调用的问题。真正要保护的不是英文词，而是思路的流畅。

## **42:36｜不写逐字稿：她要的是朋友式沟通**

我问她录视频会不会写逐字稿。她说不会，一是懒，二是读逐字稿会让她变得机械。

> 我始终还是希望跟大家是那种朋友的方式在沟通，就像我在跟你聊天一样。
我不想被一个逐字稿束缚。

她会写大纲，用 bullet 记下要讲的点。录的时候偶尔看一眼，发现漏了就回来补。

这解释了她频道的气质。她追求的不是播报式准确，而是自然感和可控性之间的平衡。大纲让内容不散，口语让人愿意听下去。

## **51:09｜为什么不急着做 YouTube：内容成本一高，心理压力就上来**

聊到能不能把小红书内容发 YouTube，她说自己在考虑，但 YouTube 中长视频的剪辑和准备工作量会高很多。

她能提高更新频率，很大原因是控制成本：

> 我不想让它变成一个非常大的项目。项目一大，门槛就高了，心理压力也更大。
我当时就是以比较 MVP 的方式上线这些视频。

她把画面、背景音乐、音效这些都清掉，先把内容讲清楚。这个选择也解释了她的涨粉路径：她不是靠精致包装起号，而是把内容生产压到自己能长期承受的成本里。

## **55:41｜她不按流量选题：这周学了什么，就分享什么**

我问她怎么选题、怎么开头、有没有变现。她笑着说自己是一个「很反常人」的账号：

> 首先我不选题，其次我没有开头，第三我没有变现。

她不是不知道选题工具有用，而是不想让视频的第一目标变成「让大家喜欢」。那样压力很大。她更愿意先学习，自己有收获，再分享给大家。

她举 Open Cloud 的例子。很多人希望她出安装教程，但网上已经有很多详细步骤了。她最后讲的是不同部署方式，因为那对她和观众更有信息增量。

这段能解释她为什么不像营销号。她有判断标准，只是标准不在「这个标题能不能爆」，而在「我这周真的学到了什么，这个东西能不能给别人增量」。

## **1:00:43｜工具会换，主线不能丢**

我们聊到 Open Cloud、Manus、Claude Code、Codex、Cursor、Lovable 等工具变化。我说很多人学习 AI 的误区，是太关注工具。

Jenny 的说法很清楚：她的工具都是边用边淘汰。找到更好的，就换；没有更好的，就先用现在的。但一直有一条主线。

> 我最终想做出来一个产品，一个大家能用的东西。
对工具本身，大概看看它能做什么就行了，不用花很多时间去研究。主要还是得看结果。

这句话对学 AI 的人很重要。工具会快速变化，今天火的工具，过几个月可能就不在工作流里了。真正稳定的是你要做什么，以及这个工具能不能帮你把结果做出来。

## **1:07:08｜跟上新工具：先记 one-liner**

我问她怎么试这么多工具，时间成本怎么解决。她引用 Claude 常说的 progressive disclosure。

看到一个新工具，她先花一两分钟看它是干嘛的，记一个 one-liner。先不用，除非当前 workflow 需要它，或者它能替代某个环节。

> 我不会去深度研究很多工具，或者横向对比。只有在它能 incrementally 把我现在的 workflow 做得更好的时候，我才会慢慢淘汰和迭代。

这是一种很省力的工具学习法。先知道它大概能做什么，需求出现时再深入。否则人很容易被工具海淹没，每天都在「学习新工具」，最后没有任何结果。

## **1:09:04｜她真实的 AI 产品工作流：Chat、文档、Code、Design、Review**

技术部分最硬的一段，是 Jenny 讲自己的产品工作流。

她现在主要用 Claude 这一套。刚有想法时，先在 Claude App 里聊。聊到方向比较清楚，再让它写 project spec、monetization、go-to-market 等文档。然后把这些 Markdown 文档导到 Claude Code，开始写功能。

我问她为什么不直接进 Code。她说，作为小白，打开 Code 或 Terminal 的心理摩擦比 Chat 大。

> 我要进入 code 模式，就得有一点点认真了。
Chat 模式可以跟它一天聊 10 个商业主意，聊完了我就不管了。

后来她要做复杂的事情，决定开始用 Claude Code Terminal。她说那是一个大转变：

> 从此一发不可收拾，每天打开 10 个 Terminal。

她的开发流程是：Chat 聊清楚，Claude Code 写 dev plan；按 dev plan 一个个做功能；每天让 session 更新所有 D files；功能差不多做完，再让 Claude Code 写 design brief，交给 Claude Design 画页面，再往回导；最近开始尝试用 Codex review Claude 写的东西，或者做 testing。

这段值得想做产品的人反复看。它不是工具名堆叠，而是一条非工程背景用户真的跑通的流程：想法怎么变文档，文档怎么变开发计划，功能怎么推进，设计怎么接上，review 和 testing 怎么补进来。

## **1:24:53｜学习 AI 的误区：别先学完知识，先挑一个小需求做**

我问她，技术小白学 AI 有什么误区。她说，单纯学工具就是误区。因为没有结果，也没有成就感。

她更建议先挑一个自己的需求，或者身边人的需求，做一个小东西。这个需求不用宏大。每天省两分钟，也算需求。

她举自己的例子：为了记录每年去几次健身房、每周喝几次奶茶，她给自己做了一个 web app。只有她一个人用，但也有登录、登出、每日更新，还连了 database。

> 每个人都有需求。工作上、生活上、兴趣爱好上，总有能让你优化的东西。

她也不喜欢先学大量 AI 知识、编程知识再动手。因为知识永远学不完。算法、基础设施、硬件、软件、产品、vibe coding，每个方向都够学几年。她更愿意边做边学，让需求倒逼自己。

这可能是整期对普通人最有用的建议：不要等自己准备好了再开始。先做一个小需求，哪怕只给自己用。做的过程会告诉你下一步该学什么。

## **1:33:24｜她怎么管上下文：Obsidian 只放项目和真会用的东西**

观众问 D files、知识图谱和 context management。Jenny 说，她很多本地 Markdown 文档放在 Obsidian，但她不会把所有文章都丢进去做「第二大脑」。

她觉得 Obsidian 里一圈一圈的图很好看，但不一定有实际用处。她也不喜欢为了将来某一天可能用到，就把自己不会读的东西全存进去。

> 我是比较挑的，不走量，走质量。
如果我要写的话，一般是手写，或者一个 project 的东西，我才会把它留在 Obsidian 里面。

她展示的结构很简单：career、产品项目、vibe coding、social media 等。项目里会有 overview、monetization、go-to-market strategy、diary、dev plan、design brief。很多内容是 Claude 写的，主要给 AI 看；自己手写的东西，她才更可能记住。

这段提醒很克制：知识库不是越大越好。对普通人来说，能回去看、能继续用、能帮助项目推进，比「存了很多」重要得多。

## **1:42:17｜时间管理：少做一点，聚焦一两个项目**

我问她有主业、创业团队、自媒体，还要试工具，时间从哪里来。她说没有什么时间管理，主要是「事做少一点」。

> 项目的话，我一次就做一两个。做多了就把自己铺得太平太分散，一个都做不完。

她筛选项目，会看几个条件：自己兴趣高、可行性强、大家可能会喜欢或用到。高频更新那段时间，她会把周日留给录制，运动、见朋友这些事情就往后放。

这段把「她为什么做得到」讲清楚了。不是她比别人多很多时间，而是某个阶段把优先级排得很硬。想做成几件事，就得接受另外一些事先不做。

## **1:44:18｜商单、信任和商业化：她不想让观众猜**

后半段最值得看的，是 Jenny 对商单和商业化的判断。

她现在不接商单，主要是不喜欢一些短视频平台的合作模式：只要求创作者讲几句话，不一定让你真的深入使用，也不允许讲好坏。她更喜欢 YouTube 上清楚标注 sponsor 的方式。

> 这是一个广告，sponsor 就是 sponsor。
但这不妨碍这个博主说，我确实用了两个礼拜，发现它哪里好、哪里不好，然后我给你推荐。

她还提出一个理想模式：品牌先付 10% 到 20% 定金，创作者认真试用两三周。好用就推荐，不好用就写详细反馈给品牌。这样博主不用讲亏心话，品牌也能拿到产品反馈。

后面她讲自己的价值观：

> 如果你给大家带来足够价值的话，这个世界就是会反馈给你价值。

她说自己现在像在「攒人品」：一直给，不急着索取。未来如果做出自己的产品，大家愿意用就来用。她也讲到「割韭菜」的边界：

> 割韭菜很多还是以一种欺骗型，或者没有那么真诚的方式才是割韭菜。
如果一个东西真的提供价值，我自己也愿意付钱买。

这段适合作为整期的收束。学 AI、做产品、做自媒体，最后都会落到同一个问题：观众为什么信你。透明的广告、真实的试用、明确的价值，才有长期关系。

## **2:09:10｜个人品牌：真诚是长期战略，开头和对标只是战术**

最后我们聊个人品牌。Jenny 说，小红书现在有点像她的明信片。别人可以看到她是谁、关注什么、做什么内容，再决定要不要合作、交流或者关注。

她给普通人的建议很朴素：

> 真诚就是必杀技。还是得多讲实话，讲自己比较认可的东西，才能长久。

我追问，如果一个普通大厂人工作五年、十年，想认真做自媒体，她有什么建议。她提醒，做自媒体有天时地利人和。前十个视频没火，不一定全是人的问题；也别因为某个阶段做起来了，就以为全是自己的能力。

她还讲了一个很好的判断：今天 distribution 可能是护城河，但当所有人都开始做，护城河也会变。她不太找对标，虽然会关注喜欢的博主，潜移默化学习他们怎么表达，但会尽量避免重复别人已经讲过的东西。

最后她补了一点很重要：开头的 hook 只对陌生博主特别重要。

> 我有一些很喜欢的博主，不管他录什么我都看。只要是这个人在发，我就会点进来。
之前对他的作品的认可，和对他这个人的信任，导致他的 hook 不用很强。

所以，对标、开头、技巧都只是战术。更大的问题是，你长期给别人提供什么价值。Jenny 这期最值得看的，也正是这里：她没有把 AI、自媒体、商业化拆成三件事。她一直在做同一件事，先自己学，做出东西，讲清楚过程，慢慢建立信任。
