> 原文：[如果你在旧系统上贴个聊天框，那说明你们团队并不真懂AI](https://www.superlinear.academy/c/main/ai-saas) · 发布于 2026-02-06 · 原始空间可能需要社区会员权限。本文保留发表时语境；其中第三方引文、发言、链接与商标不随正文重新授权。

最近和 [社区成员] 聊到一个观点：目前云厂商做 AI 的路径，大多还停留在 **“SaaS 逻辑”**。

无论是 Gemini for Firebase 还是 Gemini for Vertex，那个在产品右上角加一个AI标志，点击开启Chatbot的形式，本质上是给现有产品加了一个 AI 助手。

这种做法对用户体验的提升是线性的，因为它只是在帮你“操作”一个复杂的 GUI 或文档，并没有改变云服务的交互本质。

真正的 **AI 原生**路径，应该是把云平台的能力彻底 “Skills 化”。用Google产品比喻的话，就是”GCP（谷歌云服务） as Skills“

**什么是 “GCP as Skills”？**

它的核心逻辑是：不再强求用户去云控制台找功能，而是将 GCP 的所有 API、链接和配置逻辑，封装成一套标准化的 **“Skills”（即最新的模型工具调用格式）**。从而让用户（人或AI）可以在Cursor / Claude Code / Codex或者任何一个AI工具里，直接调用。

除了GCP这样的服务，设计师们也可以想象Figma as Skills，可以让你在Cursor里直接调用你Figma里的素材甚至审美。

**为什么这种方式更有效？**

1. **能力解耦：** 云平台不再是一个需要人去“登录”的网站，而是一系列可被调用的原子化能力。
2. **IDE 深度集成：** 当云能力变成标准 Skills 后，我们在 Cursor、Claude Code 或 Codex 等工具中，无需切换窗口，无论是开发者手动指令还是 Agent 自动执行，都能直接操控云资源。
3. **顺应 Agent 趋势：** 模型处理结构化的工具调用（Tool Calling）远比理解复杂的 CLI 命令或抓取 GUI 页面要精准得多。

**一句话总结的话，“在旧系统上贴个聊天框”是给人用的逻辑，把系统做成Skills，是给AI用的逻辑。**

**为什么大厂现在还没这么做？**

要把 Gemini 接入产品，只需要 SaaS 逻辑的资源整合；但要把产品变成 AI 的 Skill，需要产品团队**真正理解 AI 的推理与调用边界**。

目前的瓶颈在于：把 AI 接进产品很容易，但把产品重构到“懂 AI”的逻辑，对产品经理和工程师来说都是更高的要求。这个要求高在两点

1. 对AI有正确认识
2. 能坚持难而正确的事情

**结论：** 云计算/工具产品的未来，不是一个更聪明的对话框，而是一个“隐形”的、由标准化 Skills 组成的后端，让 Agent 可以无缝驱动。道理很简单，未来用你软件的，是agent，不是人。起码也是很多agent加很少的人。

### 注2:

[#AI Chatbot之后，SaaS 应该怎么被 Agent 操作？](https://www.superlinear.academy/c/main/ai-chatbot-saas-agent) 里提出来，Skills注定不是最终形态，能承载也很有限。我非常同意。这里Skills指出来的是“AI原生”的方向和团队应该走的第一步，而真正AI原生的形态和值得投入的方式，是 [社区成员] 在 [#超越DRY：AI原生软件工程的思考 ](https://www.superlinear.academy/c/ai-resources/ai-software-engineering) 里提出来的，generative kernel：

> 为了实现这种生成潜力的最大化，我们交付的就不是传统的被动的给开发者调用的软件库，而是一个“生成内核”（Generative Kernel）。它是一个给AI看的工具包。根据我的第一手探索经验，一般可以包括下面三个部分：
1. 核心套件：这是生成内核的基础，提供了不可替代的核心能力。比如对宜家家具来说，这个核心套件就是上面提到的椅子腿椅子面。
2. 引导知识：和传统的、写给人类看的文档不同，这种引导知识是一套为AI设计的知识体系，甚至可以是一个搜索引擎本身（比如作为一个MCP tool给AI提供文档搜索接口）。在AI工作时，这套知识会直接注入上下文窗口，引导代码生成。这个知识可以很详尽，包括设计哲学、最佳实践、常见陷阱等等等等。因为虽然人类读完一本书可能需要几天，但AI几秒钟就搞定了。对宜家家居来说，这可能是个100页的说明书。这个说明书不是给人看的，是给一个组装机器人看的。
3. 杠杆工具集：对于一些AI在概念上能理解，但具体实现上既繁琐又容易出错的任务（比如计算复杂UI布局的坐标），我们不强求AI从零生成，而可以提供一个高层工具就好（比如类似Mermaid的布局引擎）。这个本质是把一些成功率不高的不确定性的任务转化为确定性的任务，在关键瓶颈上提升AI的生成效率。对宜家家居来说，这是内六角螺丝刀。因为机器人虽然也可以用机械臂打螺丝，但有个螺丝刀可以让它打得又快又好。

但**“能不能把自己工具做成适合AI使用的样子”，的确是衡量团队AI认知和AI能力的第一步。**
